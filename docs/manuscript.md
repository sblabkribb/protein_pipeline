## Abstract

Recent AI-enabled protein-design workflows can generate thousands of variants per target, but their component models differ in input formats, runtime assumptions, and failure modes, and structure prediction for every candidate is often computationally impractical. We present RAPID, an orchestration-and-artifact platform for resource-aware, solubility-oriented protein redesign. RAPID executes a typed redesign request through modular tools for MSA search, inverse-folding sequence design, solubility scoring, optional structural-context generation, and AF2/ColabFold evaluation -- exposed through a standard tool interface (the Model Context Protocol, MCP) -- while recording each request, stage output, quality-control decision, and label under a stable run identifier. To allocate expensive structure-prediction calls, RAPID uses a local ESM-2-based surrogate triage layer: a deterministic diversity-aware bootstrap is labeled, candidate acquisition policies are compared by internal cross-validation, and only a selected Top-K subset is folded. In a 77-target CATH retrospective benchmark with 9,206 paired SoluProt/pLDDT records, surrogate ranking recovered high-scoring candidates substantially above random selection, with Ridge recovering 70.3% of held-out top-5 SoluProt-ranked candidates versus 5.1% for random ranking. In a separate five-target strict operating benchmark, RAPID held the AF2/ColabFold budget to 50 evaluations per target, corresponding to 0.5% of candidates under a fold-all accounting baseline. A separate 18-target structural-context ablation showed that BioEmu-containing structural-context arms primarily changed candidate-pool spread and sequence diversity rather than providing a universal aggregate score uplift. In a prospective holdout of twelve CATH targets never previously run, all 1,728 folds of a balanced 12 x 6 x 24 grid completed, and 41.7% / 21.9% / 36.4% of structural-pass variance was attributable to target, backbone-within-target, and sequence-within-backbone levels respectively. Under a pre-registered analysis plan, a hierarchical adaptive allocation policy that chooses which backbone receives the next structure-prediction call found more passing designs than post-hoc-best static allocation at matched budget caps from 23 calls per target upward (+3.46 [2.10, 4.92] designs at a cap of 40), with no benefit below that point because a mandatory per-backbone probe consumes the budget. RAPID therefore provides a reproducible orchestration, compute-allocation, and provenance layer for proxy-guided protein redesign, while leaving experimental validation to downstream assay feedback.

## 1. Introduction

Computational protein redesign has become a multi-model workflow. A practical solubility-oriented campaign now combines conservation-aware residue constraints with inverse-folding sequence design [1], structure prediction [2,3], optional structural-context generation with RFdiffusion- or ensemble-based methods [4,5], soluble-expression scoring [6], and sequence search [7]. The scientific question is often not unconstrained protein generation, but constrained redesign: starting from an existing target or scaffold, the researcher wants a tractable library of multiple-mutant variants that preserves important positions, improves computational soluble-expression likelihood, and remains structurally plausible. This framing is consistent with earlier work showing that protein expression, stability, and solubility can be improved by structure- and sequence-aware computational design, while still requiring experimental validation for final biological claims [8,9].

This setting creates an infrastructure problem. Individual models are updated rapidly and often expose different input formats, output schemas, runtime assumptions, and failure modes. When campaigns are organized as scripts and notebooks, intermediate artifacts become difficult to audit, partial reruns become unsafe, and later model replacement can force a rewrite of the analysis code. These problems grow as redesign campaigns evaluate batches of candidate sequences across targets, masking policies, backbone contexts, and scoring thresholds, then connect computational candidates to follow-up measurements and design decisions. The resulting bottleneck is therefore both computational and interpretive: large candidate sets must be generated cheaply enough to be useful, but their provenance and outcome labels must also remain organized enough to support later analysis.

The dominant downstream cost in such workflows is structure prediction. ProteinMPNN can generate hundreds or thousands of variants per target, and SoluProt can score them cheaply, but running AF2/ColabFold for every SoluProt-scored candidate is rarely justified. The practical question is therefore not only how to generate candidates, but how to decide where expensive structure-prediction evaluations should be spent and how those decisions can be interpreted once experimental feedback becomes available. A useful platform should make this decision auditable: it should preserve the full path from input to candidate, allow stored results to support multiple analyses, record assay-derived objective values in a reusable form, and expose enough model-replacement structure that new backends can be tested without changing the scientific question.

We present RAPID, an orchestration-and-artifact platform for resource-aware, solubility-oriented redesign. RAPID is a model-orchestration layer rather than a new predictive model or a universal protein-design engine: a single request is interpreted and executed by an orchestrator that dispatches modular model tools through a standard tool interface (the Model Context Protocol, MCP [10]), with stage sequencing, rule-based quality control, and recovery handling. The study is organized around three contributions. First, RAPID provides a command-driven orchestration layer that runs heterogeneous, independently-updated models behind one interface, so backends can be added or replaced without changing the scientific question. Second, on top of this layer RAPID implements and benchmarks resource-aware surrogate triage for post-SoluProt candidate selection, concentrating a fixed structure-prediction budget on a surrogate-ranked Top-K. Third, RAPID evaluates structural-context allocation by comparing candidate pools generated from the original backbone, BioEmu, RFdiffusion3 (RFD3) [11], and combined RFD3+BioEmu contexts under explicit design and AF2 budgets. Underpinning all three, every request, tool call, output, and label is written to a single run-scoped artifact record, so reruns, benchmark reconstruction, and assay-feedback evolution operate on identical artifacts.

RAPID's contribution is an orchestration-and-artifact layer rather than a new model, so it sits alongside two bodies of prior work. General workflow managers such as Nextflow [12] and Snakemake [13], and experiment-tracking tools such as MLflow [14], provide reproducible execution and data lineage but are not specialized for protein-redesign artifacts or for budgeting structure-prediction calls; domain frameworks such as BioNeMo [15] bundle protein models without a run-scoped artifact contract or a surrogate-triage budget. Relative to active-learning directed-evolution methods such as EVOLVEpro [16] and earlier solubility- and stability-oriented design work [8,9], RAPID adds a typed run-scoped artifact contract that makes heterogeneous model outputs reusable across analyses, together with an explicit fixed-budget surrogate-triage policy for allocating expensive AF2/ColabFold calls.

## 2. Methods

### 2.1 Pipeline and Artifact Contract

RAPID represents each redesign campaign as a run-scoped orchestration record rather than as a collection of disconnected scripts. Its operational workflow connects multiple-sequence-alignment (MSA) construction, optional RFD3 and BioEmu structural-context stages, ProteinMPNN design, SoluProt scoring/filtering, AF2/ColabFold evaluation, and downstream novelty reporting. MSA construction defines conservation-informed fixed-position constraints. ProteinMPNN generates multiple-mutant libraries under those constraints, SoluProt provides a low-cost soluble-expression score/filter, and AF2/ColabFold provides structural-confidence labels for selected candidates. The AlphaFold predicted local-distance difference test (pLDDT) is used only as a computational shortlisting proxy, not as evidence of experimental stability or activity.

Each run stores its typed request, stage outputs, status records, trace events, quality-control summaries, experiment records, and final summaries under a stable run identifier. Downstream analyses consume shared artifact fields rather than model-specific folders, which is the basis for partial reruns, retrospective benchmark reconstruction, and backend replacement. The local browser interface exposes the same run identifiers and request fields as the backend, but the scientific claims are based on the stored artifacts rather than on the interface itself.

Orchestration is exposed through a Model Context Protocol (MCP [10]) tool interface. A typed request -- target sequence or structure, conservation masks and position constraints, a resource budget, and a mode -- is submitted to named tools (pipeline.run, pipeline.preflight, pipeline.classify_residues, pipeline.af2_predict, pipeline.diffdock, and the feedback, experiment, and agent-event accessors), and the orchestrator sequences the stages deterministically (rule-based control, not an LLM agent), dispatching internal and external GPU services behind the same interface. Two quality-control mechanisms operate over this layer. First, an evidence-agent panel runs rule-based structure, protein, ligand, and experimental checks at each stage and records a consensus decision (proceed or recover) to a per-run agent-panel log. Second, stage-level automatic recovery substitutes a defined fallback when a backend stage fails or returns unusable output -- for example, reverting to the original target backbone when an RFD3 request fails -- and records the substitution in the run record. This stage-level recovery is distinct from the per-design ProteinMPNN fallback-sequence recovery, which is disabled in the reported benchmarks so that every reported design originates from the configured backend.

Exact per-run inference settings (model counts, recycles, sampling temperatures, RFD3 timesteps) are recorded in the artifact record.

### 2.2 Surrogate Triage and Experimental Evolution

RAPID separates two related uses of surrogates. The first is a computational structure-prediction-budgeted triage layer used in the benchmark. ProteinMPNN first generates a candidate pool across conservation tiers, and SoluProt scores every candidate. SoluProt-scored candidates passing the configured criteria are embedded with mean-pooled ESM-2 8M embeddings [17]. In deployment, this embedding stage can be backed by a GPU ESM worker, allowing large ProteinMPNN pools to be featurized without expanding the AF2/ColabFold acquisition budget. The smallest ESM-2 model (8M parameters) was chosen deliberately so that the full multi-thousand-candidate pool can be featurized in real time on modest GPU resources, consistent with the resource-aware goal of reducing the dominant AF2/ColabFold cost rather than maximizing embedding capacity; larger ESM-2 backends can be substituted under the same artifact contract, and an embedding-size sensitivity analysis (8M versus 150M, Supplementary Note 3) confirms that the larger model does not materially improve the budget-governing acquisition metrics, so the 8M model is retained as the resource-aware default. K-means selects a diverse bootstrap training set, AF2 labels those candidates, and local surrogate policies are compared by internal cross-validation on the labeled set. The selected acquisition policy is then refit on all bootstrap labels and used to rank the remaining SoluProt-scored pool; only that policy’s Top-K candidates are sent to AF2/ColabFold. The implemented comparators include Random Forest, Ridge, XGBoost, and LightGBM, with K-means used for bootstrap selection and Bayesian-optimization-inspired criteria used for acquisition ranking [18-23]. In the software, this triage layer is a switchable component after SoluProt and can be combined with optional upstream RFD3 or BioEmu stages. In the benchmark, it is evaluated on original-backbone candidate pools to isolate compute allocation from structural-context exploration.

The production triage default uses one shared budget across the selected 30%, 50%, and 70% conservation tiers. In the manuscript benchmark, this layer is evaluated with the original target backbone and without RFD3 or BioEmu-generated candidate pools so that the fixed-budget triage result is not conflated with structural-context expansion. By default, ProteinMPNN requests 3,333 candidates per tier, giving a nominal 9,999 designs before validation and SoluProt filtering. RAPID then labels 30 K-means-selected bootstrap candidates from the pooled SoluProt-scored set and evaluates 20 Top-K AF2 acquisitions from the same pooled set. The N = 30 bootstrap was chosen because the sample-size ablation reaches most of the observed Random Forest pLDDT uplift by that point, while Top-K = 20 fixes a target-level validation budget that is large enough for manual review but small enough to keep the AF2 cost explicit. RAPID compares surrogate policies on the same labeled bootstrap set and uses only one selected acquisition policy for the final Top-K. Detailed audit outputs are described in the supplement and release package.

The second use is an experimental-feedback evolution mode. In this mode, RAPID generates a SoluProt-scored candidate pool when no experimental labels are available. Users can later record assay outcomes through stable candidate or sequence identifiers, objective metrics, measurement directions, and replicate metadata. When labels for a specified objective metric are present, RAPID trains a local surrogate on the labeled sequences and writes a next-candidate recommendation table for the next design-test-learn cycle. This interface is related to active-learning directed-evolution frameworks such as EVOLVEpro, but the present manuscript treats it as an assay-feedback handoff rather than as a prospective experimental validation result [16]. A legacy AF2-oracle label source preserves the earlier computational comparison mode, but the default evolution label source is experimental feedback.

This separation is important because computational shortlisting and experimental evidence are different label sources. The surrogate-triage mode reduces how many candidates require expensive structure prediction before a shortlist is made, whereas experimental-feedback evolution defines how a shortlist can re-enter the system after expression, solubility, activity, or stability assays. Operationally, RAPID produces traceable shortlists and experiment-request records, while physical measurements are performed outside the software and re-enter RAPID only as labeled outcomes (see Supplementary Note 11 for an illustrative data-trace schema). This data pathway is intended to support future experimental evaluation rather than to serve as prospective validation in the present benchmark. The artifact contract allows a later campaign to ask whether a model, masking rule, or backbone context changed the distribution of candidates without manually reconstructing which files, scores, and assay records belonged to each decision.

### 2.3 Benchmark Analyses

The current stored artifact benchmark contains 9,206 paired SoluProt and pLDDT records from 77 QC-passing CATH runs in the corrected-chain refresh [24]. The refresh applies the corrected chain-selection contract introduced after the original archive and is used in the main text as component-level evidence for structure-prediction-budgeted surrogate triage rather than as a definitive population-level performance estimate. Runs with fallback sequences, invalid amino-acid records, missing conservation tiers, or insufficient paired SoluProt/pLDDT records were excluded. The full 115-run corrected-chain archive and QC details are reported in Supplementary Notes 1 and 2.

The primary surrogate-triage metrics are Spearman rank correlation, Top-K recall, and Bayesian-optimization (BO) uplift Top-K. BO uplift measures the difference between the mean observed score of the surrogate-selected Top-K and the mean score of K random draws from the same held-out pool. Paired comparisons use Wilcoxon signed-rank tests with Holm correction, effect-size interpretation uses Cliff’s dominance statistic, and uncertainty is estimated by cluster bootstrap with target as the cluster [25-27]. Variance decomposition uses a one-way ANOVA intraclass correlation coefficient (ICC(1,1)) to estimate how much score variation is attributable to target identity [28]. All stochastic steps use fixed random seeds (K-means initialization via k-means++, surrogate model fitting, and the target-clustered bootstrap); the acquisition-bias analysis is additionally repeated over five seeds (7, 42, 123, 2024, 31337) to confirm the reported effects are seed-stable (Supplementary Note 7).

The strict five-target surrogate-triage run used the original target backbone, disabled RFD3, BioEmu, and Relax, requested 3,333 ProteinMPNN candidates for each of the 30%, 50%, and 70% conservation tiers, used GPU-backed ESM embeddings, and disabled fallback sequence recovery. Wild-type (WT) SoluProt and ColabFold baselines were then computed once per target as reference points for interpretation; these WT baseline calls were not used for surrogate training, Top-K acquisition, or the 250-candidate triage-budget count. Structural-context effects were analyzed separately in a corrected-chain 18-target ablation comparing the original target backbone, BioEmu conformational samples, a selected RFD3 backbone, and RFD3+BioEmu under matched design and AF2 budgets. BioEmu-containing arms were considered quantitatively evaluable only when the requested near-target conformers passed the fixed 2.0 Å target-RMSD gate. As a directional corroboration of the selected-set diversity result, a separate five-enzyme monomer panel (IsPETase, DhaA, TEV protease, CALB, and HRP-C) was analyzed with the same single-backbone, RFD3+BioEmu pool, and RFD3+BioEmu surrogate-selected comparison used in Supplementary Note 14; this panel was not treated as an independently powered significance test. Detailed per-model, per-target, and QC tables are reported in the supplement.

### 2.4 Prospective Allocation Holdout

The allocation analyses in Section 3.4 use a separate prospective holdout rather than the stored retrospective benchmark. Twelve CATH targets were selected before any folding, four from each of three length strata (50-150, 150-250, 250-400 residues), using only structural eligibility and length; no yield information existed for these targets because they had never been run through the pipeline. The target list, the substitution rule for targets whose backbone generation failed, and the reserve ordering were frozen and committed before generation began. For each target, one native backbone and five RFD3 backbones passing the fixed 2.0 A target-RMSD acceptance gate were carried forward, and 24 ProteinMPNN sequences were generated per backbone at a single temperature (T = 0.1), giving 12 x 6 x 24 = 1,728 AF2/ColabFold folds. All 1,728 completed. The RFD3-only subset (12 x 5 x 24 = 1,440) is fully balanced with structure source held constant and is used as the primary cohort; the native backbones enter only as a sensitivity analysis, because one native backbone per target makes backbone-level comparison unbalanced.

Structural agreement uses a frozen metric: sequence-order correspondence between design and reference, non-loop CA atoms selected by DSSP on the reference, and Kabsch superposition. The metric refuses to score a pair whose non-X residue count differs from the reference, rather than pairing by residue number, which is incorrect for AF2 models. Forty-eight rows were refused on this basis; all are native backbones and none fall in the primary cohort.

The analysis plan was frozen before the grid completed and is stored with the data. It fixes the primary endpoint (joint-pass designs found within a budget cap, where joint-pass is pLDDT >= 85 and non-loop RMSD <= 2.0 A and SoluProt >= 0.5), the cluster unit (target), the bootstrap (target-clustered), the minimum number of informative clusters (8), and the rule by which a target is uninformative (all arms at yield 0 or all at yield 1). It also records that the three thresholds predate the campaign and were not re-selected here. Eleven of the twelve targets were informative. Because every cell of the grid was observed, allocation policies are compared by exact replay: each policy draws without replacement from the observed outcomes, sees only the Gate 0 prior and its own probes, and cannot access the true backbone yields.

## 3. Results

### 3.1 Orchestration and Reusable Artifact Substrate

RAPID runs heterogeneous, independently-updated models behind a single orchestration interface and writes their outputs to one run-scoped record, making them reusable across analyses. In the current artifact benchmark, K-means versus random selection, surrogate-family comparison, sample-size ablation, rank-mean ensemble testing, acquisition-bias analysis, and variance decomposition were all regenerated from the same 9,206 stored AF2/SoluProt records rather than from separately refolded datasets. This supports the orchestration-and-artifact claim without requiring RAPID to be interpreted as a new predictive model.

The orchestration layer is directly observable in the stored records. The stored QC layer defines the analysis corpus: of 115 completed CATH runs, 77 passed the per-run QC rule (all three conservation tiers, at least 100 valid non-fallback design sequences, and at least 100 paired SoluProt/pLDDT records) and 38 were excluded as incomplete or fallback-only (Supplementary Note 2), with stage-level recovery and exclusions logged per run. Structural-context backbone routing is demonstrated rather than asserted: the ablation routed the original-backbone, RFD3, and BioEmu structural-context sources through the identical downstream ProteinMPNN -\> SoluProt -\> AF2/ColabFold path and wrote the same artifact fields, so the structure-generation backend was swapped without modifying the downstream analysis code or the benchmark scripts that consume the results.

### 3.2 Surrogate-Triage Fixed-Budget Benchmark

The surrogate-triage result is a fixed-budget compute-allocation result rather than a biological enrichment result. RAPID applied one shared AF2/ColabFold validation budget per target: 30 K-means bootstrap labels and 20 surrogate-acquired Top-K candidates, totalling 50 AF2/ColabFold evaluations per target across the selected 30%, 50%, and 70% conservation tiers. The strict five-target run used the original target backbone, disabled RFD3, BioEmu, and Relax, and requested 3,333 ProteinMPNN candidates per tier. Across 49,946 pooled candidates entering triage, RAPID therefore evaluated 250 AF2/ColabFold records in total (150 bootstrap labels and 100 Top-K acquisitions across the five targets; per-target run and WT-reference details in Supplementary Note 9). This comparison is reported only as a fold-all accounting baseline -- the number of AF2/ColabFold evaluations that folding every candidate entering triage would require -- not as a model-performance claim. In these strict runs the pool entering triage was essentially the full validated ProteinMPNN set (9,954–9,999 candidates per target), so SoluProt acted as a ranking score rather than as a restrictive pass/fail gate at the thresholds used. The five-target run and the retrospective benchmark below play complementary roles: the former fixes the end-to-end operating point — how many AF2/ColabFold evaluations a real run actually spends — whereas the latter quantifies whether the surrogate's ranking recovers high-scoring candidates.

Surrogate acquisition quality was evaluated in a separate retrospective benchmark in which fully labeled held-out pools were available, allowing Top-K recall and BO uplift to be measured directly (Supplementary Note 5). With 30 K-means bootstrap labels, Ridge recovered 70.3% (95% CI 66.4-74.3%) of the held-out top-5 SoluProt-ranked candidates compared with 5.1% (4.2-6.0%) for random ranking, while Random Forest improved pLDDT Top-5 recall relative to random ranking (13.1%, 95% CI 10.6-15.6%, versus 5.5%, 4.6-6.4%; paired Wilcoxon with Holm correction p = 4.1e-13, Cliff's delta = 0.26) and produced a mean pLDDT Top-5 BO uplift of 1.055. Confidence intervals are target-clustered bootstrap intervals; the full per-model comparison is given in Supplementary Note 5. Because these comparisons are made within identical ProteinMPNN-generated held-out pools, the recall differences reflect the surrogate ranking step rather than differences in candidate-pool composition. This retrospective evidence supports allocating the fixed AF2/ColabFold budget to surrogate-selected Top-K candidates rather than to random selection.

### 3.3 Structural-Context Exploration

The structural-context result is a separate candidate-pool-generation analysis rather than an extension of the five-target surrogate-budget result. The relevant question is not whether an alternative context improves the aggregate mean or the best-scoring candidate, but whether it changes the accessible candidate distribution under the same downstream budget. Target identity explained 98.8% of pLDDT variance and 96.8% of SoluProt variance in the stored benchmark, indicating that deeper sampling of one local pool is not the only relevant allocation problem. A single-backbone ProteinMPNN pool can concentrate candidates around one local geometry and may under-sample alternative local contexts; any downstream selector can only choose among candidates already generated in that context. In the corrected-chain ablation, alternative contexts did not provide a consistent mean-score advantage. Paired Wilcoxon signed-rank tests were Holm-corrected across the 12-test family (four pool-level metrics x three context arms). Five shifts survived correction: BioEmu broadened pLDDT range and sequence-pool diversity in all eleven evaluable paired targets and SoluProt range in 10 of 11 (raw p = 0.001-0.002, Holm p = 0.012-0.020), and RFD3+BioEmu broadened both pLDDT range and sequence diversity in all ten evaluable paired targets (raw p = 0.002, Holm p = 0.020 for both). The remaining shifts were nominal and did not survive correction, and are reported as trends only: RFD3-alone broadened pLDDT range (14 of 18; raw p = 0.012, Holm p = 0.068) and sequence diversity (9 of 18; raw p = 0.039, Holm p = 0.118), the RFD3+BioEmu SoluProt-range gain (8 of 10; raw p = 0.020, Holm p = 0.078), and a small BioEmu mean-pLDDT decrease (raw p = 0.010, Holm p = 0.068). The robust, correction-surviving signal is therefore that single-backbone pools under-sample the pLDDT range, sequence diversity, and (for BioEmu) the SoluProt range that the BioEmu and RFD3+BioEmu ensemble contexts broaden. RFD3 and BioEmu are accordingly treated as controlled context-perturbation modules with explicit QC, not as default score boosters or surrogate-model components.

This pool-level diversity broadening is preserved through surrogate triage rather than lost at selection. Nine RFD3+BioEmu targets were run end-to-end under the strict fixed-budget triage operating point, each with a matched single-backbone triage run at the same budget. The surrogate-selected Top-K from the RFD3+BioEmu pool was markedly more sequence-diverse than the single-backbone selection (mean pairwise diversity 0.31 vs 0.11; more diverse in 9 of 9 targets, mean 4.2-fold; paired Wilcoxon p = 0.0039), at comparable structural confidence (selected-set mean pLDDT 95.0 vs 96.4) and solubility (mean SoluProt 0.71 vs 0.71). The diversity originates in the structural-context expansion and is preserved, not created, by the surrogate: a pool-representative random sample of the RFD3+BioEmu pool was itself diverse (0.35), and surrogate selection retained most of that diversity (0.31), whereas single-backbone surrogate selection frequently collapsed toward near-duplicate sequences (Figure 4; Supplementary Note 14). The structural-context diversity gain is therefore realized in the candidates actually advanced under a fixed compute budget, with comparable selected-set pLDDT and SoluProt means. This is a diversity result rather than a pLDDT- or SoluProt-improvement claim: within the expanded pools, surrogate selection did not significantly change selected-set pLDDT relative to that bootstrap (mean +0.2 pLDDT, n = 9, Wilcoxon p = 0.43). The same selected-set diversity pattern was independently reproduced on five real solubility-engineering monomer enzymes from a separate curated benchmark (IsPETase, CALB, TEV protease, DhaA, and HRP-C), with the expanded selection more sequence-diverse than the single-backbone selection in all five at comparable pLDDT and maintained-or-improved SoluProt; because that set has only five targets it is treated as a directional corroboration rather than an independently powered test (Supplementary Note 14).

### 3.4 Prospective Allocation on Unseen Targets

The preceding sections allocate a fixed budget across candidate sequences within a pool. This section asks the complementary question -- which backbone should receive the next structure-prediction call -- on targets the routing model never saw.

Variance in the balanced prospective cohort is distributed across all three levels. In a sum-of-squares decomposition of structural pass on the 1,440-design RFD3 cohort, 41.7% is attributable to target-level differences, 21.9% to backbone differences within target, and 36.4% to sequence differences within backbone; target and backbone together account for 63.6%. A mixed model with length stratum as a fixed effect and nested target and backbone random effects gives 52.9% target-level variance for pLDDT and 40.2% for RMSD, so the target-level component is not an artifact of protein length -- shorter domains do fold better (+3.50 pLDDT and -1.59 A for the 50-150 stratum against the 150-250 reference), but target variance survives adjustment for it. The corresponding figure in the earlier temperature-panel cohort is 64.2%, which we report as a supplementary consistency check rather than as independent corroboration: that cohort contains 20 targets and was deliberately built from mid-yield backbones, so the two are not a replication. What it does establish is that removing the selection barely moves the attribution. These percentages are a variance attribution within an observed cohort, not a causal decomposition, and they are a different quantity from the ICC(1,1) target-identity figures reported for the stored retrospective benchmark in Section 3.3.

Because backbone-level differences are large within a target, the order in which backbones are probed matters. Against static allocation whose number of backbones k is chosen post hoc at its best value -- an advantage a real user does not have -- the hierarchical adaptive policy finds more joint-pass designs at matched budget caps, with target-clustered bootstrap intervals excluding zero from a cap of 23 calls per target upward: +0.48 [0.23, 0.75] at 24, +3.46 [2.10, 4.92] at 40, +6.21 [3.68, 9.14] at 60, and +6.44 [3.48, 9.42] at 80. Where it helps, it captures roughly 70% of the gap between uniform allocation and an oracle that knows the true backbone yields.

The shape of that curve is as informative as its peak. Below a cap of about 23 there is no benefit, because the mandatory four-sequence probe on each of five backbones consumes the entire budget and leaves nothing to allocate; the policy pays its floor and buys nothing. At a cap of 120 every policy has observed every available fold, so all of them must converge, and they do (74.9 to 75.6 designs against an oracle's 75.6). That convergence is a correctness check on the replay rather than a finding.

Budget cap and realized compute differ, and we report them separately rather than redefining the pre-registered endpoint. The adaptive policy abandons backbones with no remaining movability and leaves the rest of its allowance unspent, whereas static allocation always spends its cap. At a cap of 120 the primary endpoint reads -0.24 [-0.58, 0.00] designs, and the same runs used 106.4 calls rather than 120. Giving static allocation only the calls the adaptive policy actually consumed reverses the sign to +0.71 [0.00, 1.75]; because that interval touches zero, the defensible statement at saturation is that the two are indistinguishable while one spends 13.6 fewer calls. Away from saturation the matched-compute comparison agrees with the primary one (+3.62 [2.29, 4.99] at a cap of 40). Asking the reverse question -- how many calls static allocation needs to match the number of designs the adaptive policy found -- gives 15 to 18 fewer calls for the adaptive policy between caps of 40 and 100, with intervals excluding zero, and +0.86 [0.19, 1.98] in the other direction at a cap of 20, the same probe-floor boundary. On a compute-versus-yield Pareto frontier, uniform allocation holds the caps from 12 to 20 and the adaptive policy holds every point from 24 upward.

These results validate the backbone-allocation axis only. The grid was generated at a single ProteinMPNN temperature, so the condition-exploration term of the policy was inert here. That axis is tested separately in a 832-fold temperature panel, where T = 0.1 gave the highest structural yield (0.4952) against 0.4135 at T = 0.05, 0.4135 at T = 0.2, and 0.3990 at T = 0.3, all three paired differences excluding zero over ten informative target clusters. That panel selected mid-yield backbones by construction and is therefore used to establish the condition effect, not to support policy-performance claims.

## 4. Discussion

RAPID addresses a practical bottleneck in AI-enabled protein redesign: heterogeneous, independently-updated models must be composed, expensive structure-prediction evaluations must be allocated across large candidate pools, and the whole process must stay auditable. Its contribution is not a new protein-design model but a command-driven orchestration layer that dispatches modular model tools through a standard interface (the Model Context Protocol), sequences stages with rule-based quality control and recovery handling, and writes every request, tool call, and output to a run-scoped record. By turning expensive model calls into typed artifacts under stable run identifiers, this layer makes model composition, backend replacement, artifact reuse, and retrospective analysis practical for solubility-aware redesign.

This artifact contract has workflow-scale consequences. In the present benchmark, multiple surrogate, selection-size, diversity, and variance analyses were regenerated from the same 9,206 paired SoluProt/pLDDT records rather than from separately refolded datasets. In the strict surrogate-budget runs, thousands of SoluProt-scored candidates were reduced to tens of AF2/ColabFold evaluations while preserving the candidate identifiers needed for downstream review. These examples do not establish experimental performance, but they show that large computational batches can become reusable decision context rather than disposable model-output folders.

The surrogate-triage result is similarly bounded. The evidence supports a structure-prediction allocation policy, not an experimental hit-rate claim. K-means provides a deterministic and diversity-aware cold-start bootstrap, Random Forest acts as a conservative pLDDT acquisition reference, Ridge is useful for SoluProt-oriented ranking, and N = 30 is a cost-efficient bootstrap point. RAPID uses these observations to define comparator policies, then selects one acquisition policy by internal cross-validation for each run. The retrospective pooled-scaling guardrail (Supplementary Note 10) shows that simple pooled accumulation without target conditioning does not monotonically improve ranking performance, supporting the current default of lightweight per-run calibration rather than premature replacement by a global surrogate.

A likely reason for this guardrail is target heterogeneity. Sequence length, fold class, disorder or low-complexity propensity, MSA depth, conservation pattern, and backbone context can all change how sequence edits map to pLDDT or soluble-expression proxies. A pooled model trained before these factors are explicitly conditioned may therefore learn target-level offsets or context-specific noise rather than a transferable acquisition rule. The same logic applies to diversity: the observed acquisition bias (Supplementary Note 7) suggests that future policies should combine predicted quality with explicit ESM-space diversity constraints under a tunable quality-diversity trade-off, such as max-min filtering, cluster-balanced Top-K selection, or determinantal point processes, instead of relying on score ranking alone [29]. In this view, RAPID’s longer-term role is to accumulate AF2 labels, assay labels, paired rankings, target metadata, structural context, conservation tiers, and sequence-edit histories into a preference dataset that can later support target-conditioned preference models that take CATH class and structural metadata as explicit conditioning inputs.

The structural-context result reframes backbone and ensemble stages as context-sensitivity probes. Target identity dominates the stored benchmark, and the corrected-chain structural-context ablation shows target-dependent tradeoffs under matched AF2 caps. A single-backbone ProteinMPNN pool can overrepresent sequences compatible with one local geometry; downstream triage can rank that local neighborhood efficiently but cannot recover candidates that were never generated. The useful signal is therefore the paired change in score spread and sequence diversity, not an aggregate claim that one structural-context module improves quality. After Holm correction across the test family, the surviving shifts were BioEmu's broader pLDDT range, sequence diversity, and SoluProt range, and RFD3+BioEmu's broader pLDDT range and sequence diversity; the remaining context shifts, including the RFD3-alone effects, were nominal trends only. This pattern supports treating RFD3 and BioEmu as controlled exploration modules with explicit QC rather than as default score-improvement modules.

The model-replacement claim is demonstrated for the structure-generation backend and architectural for the others. In the structural-context ablation, the original-backbone, RFD3, and BioEmu structural-context sources were routed through the same downstream ProteinMPNN -\> SoluProt -\> AF2/ColabFold path and wrote the same artifact fields, so the structure-generation backend was replaced without redesigning the downstream analysis; the same contract is available for the inverse-folding, solubility, and relax backends, whose numerical operating point should be re-estimated after replacement.

## 5. Limitations

The prospective allocation result carries its own bounds. It rests on twelve targets, so the variance components -- and the target-level component in particular, estimated from twelve clusters -- should not be read as precise point estimates; balancing the cohort removes the selection concern but not the sampling uncertainty. The grid was generated at a single ProteinMPNN temperature, so the condition-exploration half of the allocation policy is untested in this cohort. Policy comparison is exact replay of a fully observed grid rather than online execution: each backbone carries only 24 observed sequences, so a policy that concentrates on one backbone must move on where a live run could generate more, which understates rather than inflates the adaptive advantage. The RFD3 backbones all passed the 2.0 A acceptance gate, so variation among rejected backbones is unobserved. Two comparator choices favour the baseline deliberately -- only the adaptive policy pays its probe cost out of the budget, and the static comparator's k is chosen post hoc at its best value.

Two auxiliary analyses are reported as annotation rather than evidence. The ThermoMPNN stability comparison is retained as annotation and tie-break only: its correlation with pLDDT is +0.21 pooled but -0.17 within backbone, negative in seven of eight backbones, so the pooled figure reflects between-backbone difficulty and is not used as a ranking basis. The ligand self-docking result is a wiring and sanity check, not a binding-performance claim, because DiffDock was trained on PDBBind and these complexes are likely within it.

The current evidence is computational and proxy-based. pLDDT and SoluProt scores do not establish soluble expression, thermodynamic stability, or activity without experimental validation. The experimental-feedback evolution interface can ingest assay labels and recommend the next candidate set, but no prospective experimental enrichment result is claimed here. RAPID should therefore be interpreted as a reproducible artifact and compute-allocation layer for proxy-guided redesign, not as evidence that the selected candidates have been experimentally validated.

The current surrogate-triage benchmark is based on a 77-target QC-passing artifact set from the corrected-chain CATH refresh, so it should be interpreted as component-level evidence for an AF2/ColabFold triage workflow rather than as a definitive population-level performance estimate. The completed archive was sufficient to test pooled surrogate accumulation, but not to show a stable pooled-model advantage over target-specific calibration; we therefore treat this result as support for the current per-run adaptive default and as motivation for future preference-dataset accumulation. The corrected-chain structural-context ablation covers 18 targets, with BioEmu quantitatively evaluable for eleven targets and RFD3+BioEmu for ten under the fixed RMSD gate. This is sufficient to test structural-context allocation as a workflow variable, but not to claim a universal advantage for RFD3, BioEmu, or their combination. Reproducibility scope also differs by analysis: the strict five-target surrogate-budget views and the structural-context ablation tables are released as per-design CSVs and can be regenerated directly, and the full per-design records underlying the 77-target surrogate-family analyses (Supplementary Notes 2-8) are likewise released -- per-design sequences, pLDDT, and SoluProt with the matching ESM-2 8M (320-D) and 150M (640-D) embeddings under `public_data/benchmark/refresh/` -- so those analyses can be regenerated directly from released files.

## 6. Conclusion

RAPID provides an orchestration-and-artifact layer for resource-aware, solubility-oriented protein redesign. A single request is executed by an orchestration layer that dispatches modular model tools through a standard interface (MCP), so heterogeneous, independently-updated backends can be rerun, replaced, and analyzed without rebuilding the workflow around each one. On top of this layer, the surrogate-triage mode allocates AF2/ColabFold evaluations to a small, auditable Top-K subset after SoluProt scoring, while preserving comparator-model evidence for review. Every request, tool call, output, quality-control record, and label is preserved under a stable run identifier, giving a reproducible substrate for the surrogate and structural-context analyses.

The present evaluation supports RAPID as a reproducible artifact and compute-allocation framework rather than as an experimentally validated design model. RAPID makes fragmented model outputs reusable, reduces structure-prediction calls under an explicit triage budget, and makes structural-context allocation testable across single-backbone, BioEmu, RFD3, and combined contexts. Its longer-term value is the reusable learning substrate created as computational labels, assay labels, target metadata, and structural-context decisions accumulate under the same artifact contract. Although the present study focuses on solubility-oriented redesign, the same triage pattern can be extended to other objectives when suitable low-cost proxies and prospective validation assays are available.

Only the bulk raw run outputs (per-run MSAs, predicted structures, and AF2/ColabFold PDB/PAE files) are too large to host in this source tree and remain available from the authors on request.
